# Recording, Replay and filtering

Recording is **off by default**. Start a participant, obtain consent, check the consent box, then explicitly Start recording. Consent resets for each participant. Stop recording, End/reset, disconnect or backend shutdown closes the recording. Browser reconnect does not stop acquisition recording.

JSONL files are created exclusively under ignored `recordings/` with generated IDs. Header includes participant configuration, headset metadata and subscription/channel schemas. Valid samples are recorded on the Cortex acquisition path before browser buffer eviction, including timestamps, normalized channels, raw schema-labelled values (including Cortex counters/markers), quality samples and interpolation flags. Actual activity/training/Temi events are markers. Closing writes a summary with reported loss and byte count. Files cap at 512 MiB and stop with a loss report on write/size failures; no recording queue grows without bound. Disk write buffering is not crash-proof, and abrupt power/process loss can truncate a file; hardware acceptance must measure sustained recording performance. Recording is independent of the intentionally lossy browser feed, not a guarantee against upstream headset/Cortex or storage loss.

Diagnostics distinguish duplicate and out-of-order rejection, pending RPC notification overflow, bounded visualization-buffer evictions, and timestamp-gap estimates based on the verified headset `settings.eegRate`. Recording reported loss includes malformed/reordered samples, notification overflow and estimated upstream gaps while recording. Gap estimates are approximate and can overlap notification losses; do not interpret their sum as an exact count. Preserve `eq.sampleRateQuality` to assess vendor-reported upstream loss; this application cannot prove unseen losses without hardware comparison. No assumed 128 Hz rate is used.

To replay, end the participant and stop recording. List recordings, select one and Start Replay. Actual recorded measurements are paced by their timestamps. Replay remains visibly labelled at EOF and after errors until Exit Replay; it blocks participant/profile/Temi commands in both UI and backend. Incoming live samples are ignored for display during Replay; Cortex is not unnecessarily reopened. Exiting clears all replay history. Malformed recordings pause with an explicit error. No new estimates or robot expressions are generated from Replay.

Optional filtering: `python -m pip install -r requirements-filter.txt`. Enable the 1–40 Hz filtered view in Operator tools and select Filtered view in waveforms. Filtering requires the **actual** Cortex headset `settings.eegRate`; unavailable metadata disables it, changed metadata turns it off, and no operator-entered guess substitutes for it. Implementation uses fourth-order Butterworth bandpass second-order sections with SciPy `sosfilt`, initialized per channel and carrying state between samples. Raw EEG and raw recordings remain available. Delay is causal and frequency-dependent, not zero-phase. A bandpass Butterworth order 4 has effective bandpass order 8. States reset across gaps >2 acquisition periods, rate changes and participant resets. It is a display option, not artifact rejection or a diagnostic signal-processing pipeline. Replay currently displays recorded raw EEG; filtering is a live view. Offline noncausal analysis is not implemented.

References: [SciPy butter](https://docs.scipy.org/doc/scipy/reference/generated/scipy.signal.butter.html), [sosfilt](https://docs.scipy.org/doc/scipy/reference/generated/scipy.signal.sosfilt.html), [Cortex headset settings](https://emotiv.gitbook.io/cortex-api/headset/queryheadsets).

Future Lab Streaming Layer integration belongs at the backend acquisition/event boundary before the browser feed. It could publish timestamped EEG and event outlets for synchronized external recording, with explicit clock correction and loss accounting. LSL is not a runtime dependency and no synchronization capability is currently claimed.
